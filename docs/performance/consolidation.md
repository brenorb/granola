## Rejected experiments and remaining opportunities

- **Order-key reuse:** keep fresh per-reservation identities. The isolated offline
  experiment at `perf/order-key-experiment`, commit `8f71648`, measured three fresh
  keys at about 0.278 ms versus 0.269 ms with Nostr reused in memory: approximately
  0.009 ms saved. Real key lookup added storage work (about 0.5 ms including key
  preparation with one stored order). Three live pairs did not demonstrate the
  requested 0.5-second saving. The user explicitly chose to retain isolation if
  that target was not met. The experimental identity changes must not be merged.
  Reproduction and raw measurements remain at that commit under
  `docs/performance/2026-09-06-isolated-key-profile.md` and its linked JSON files.
- **Additional metadata warmup:** rejected because explicit preflight refresh
  would still issue 12 post-click requests and warmup would add traffic. Changing
  the freshness policy remains open, with active-keyset rotation, ambiguous mint
  responses and recovery tests required. See [review](2026-09-06-mint-prewarm.md).
- **Shared proof-observer registry:** prototype removed; no reachable concurrent
  duplicate proof set was found. Notifications remain wakeup hints, not spend
  evidence. See [review](2026-09-06-proof-observers.md).
- **Attribution:** fewer requests, CPU operations or checkpoints do not alone
  prove a faster complete swap. The final local optimizations removed 40–41
  IndexedDB operations/decryptions in the observed swaps, but historical versus
  candidate median wall time increased from 13.90 to 16.54 seconds. The samples
  were not a contemporaneous randomized A/B. Do not sum overlapping wallet, CPU,
  storage and network intervals, or call unclassified residual time local CPU.
  Request count and sequencing remain our responsibility even when requests
  wait on third-party mints and relays.

## Contract consolidation

The later SDK/specification commit reintroduced outdated descriptions. The
protocol reference now reflects three private messages, authenticated direct
routes, asynchronous durable announcements, financial completion based on mint
evidence, and the 10/20/30-minute profile generated by the implementation.
Settlement evidence remains private. No runtime rollback to the older described
protocol is needed.

The redundant public `expires_at` tag is removed from the PoC wire format.
The order body's deadline and its standard NIP-40 `expiration` tag remain bound
and validated. Existing builds that require both tags need updating.

Validation of this consolidation: 443 tests passed, seven skipped; typecheck,
production build and `git diff --check` passed. The new regression covers the
single-tag output and rejects missing, duplicated or mismatched expiration.
No new live-network benchmark was run; performance numbers above are historical.
